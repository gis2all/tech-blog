# Decap CMS 全局标签库设计

## 背景

当前 `decap` 分支已完成 Decap CMS 第一阶段的基础增强：中文界面、内容列表摘要与筛选排序、分类枚举、专题关联、字段提示与顺序、文章轻量预览，以及固定为 `4322` 端口的本地后端调试。

文章标签目前通过自定义 `tag_selector` 控件从 `src/data/tag-library.json` 搜索并多选，但新文章只能选择标签库中已有的标签。创建新标签必须先离开文章编辑页进入标签库，打断写作流程。本设计在保留 Decap 原生后台的前提下补齐标签创建、同步和安全删除能力，不重写 CMS。

## 目标

- 新建或编辑文章时，可以搜索并选择已有标签。
- 输入不存在的标签时，显示 `创建“标签名”`，按 Enter 或点击后加入当前文章。
- 新标签在文章保存成功前只存在于当前表单中。
- 保存文章时，将新标签自动加入全局标签库。
- 文章与标签库在同一次后端保存中提交，同时成功或同时失败。
- 文章标签上的移除操作只解除当前文章关联，不删除全局标签。
- 全局标签只能在标签库页面删除；使用中的标签禁止删除，未使用标签需二次确认。
- 本地 Proxy 后端与线上 GitHub 后端行为一致。

## 非目标

- 不自动合并大小写不同的历史标签，例如 `Git` 与 `git` 继续视为不同标签。
- 不自动清理没有文章使用的标签。
- 不提供标签重命名、批量合并或批量迁移文章能力。
- 不建设独立内容数据库、服务端 API 或自定义 CMS 仪表盘。
- 不改变文章 frontmatter 的 `tags: string[]` 数据结构。

## 交互设计

### 文章标签控件

标签输入框继续提供多选和键盘操作。输入内容先去除首尾空格，再进行匹配：

1. 完全同名标签已在当前文章中时，不重复添加。
2. 完全同名标签存在于全局标签库时，选择并复用该标签。
3. 不存在完全同名标签时，在建议列表末尾显示 `创建“标签名”`。
4. 选择创建项后，新标签立即显示在当前文章的已选标签区域，但不立即修改 `tag-library.json`。
5. 标签上的 `x` 只从当前文章表单中移除该标签。

待保存标签与已有标签在文章表单中采用相同的标签样式，避免增加不必要的状态负担。创建后显示简短状态文字“保存文章后加入标签库”。

### 标签库管理控件

标签库页面使用专用管理控件，不直接暴露容易误操作的通用字符串列表：

- 每个标签显示名称和当前文章使用次数。
- 使用次数大于零时，删除按钮禁用，并说明仍有多少篇文章使用。
- 使用次数为零时允许删除，但必须经过二次确认。
- 从最后一篇文章移除某标签后，该标签仍保留在标签库，直到用户在此页面手动删除。
- 标签库加载或文章使用情况统计失败时禁用删除，不能以未知使用状态执行破坏性操作。

## 架构

实现由三个边界清晰的部分组成：

### 1. 标签领域工具

无 UI、无后端依赖的纯函数负责：

- 去除标签首尾空格。
- 按完全同名规则去重并保留既有大小写。
- 计算文章最终标签中尚未进入标签库的标签。
- 合并并稳定排序标签库。
- 根据文章集合统计每个标签的使用次数。
- 判断标签是否允许删除。

这些规则由单元测试直接覆盖，文章控件和标签库控件共用同一套结果，避免两处规则漂移。

### 2. CMS 控件

- `tag_selector` 负责文章中的搜索、选择、创建待保存标签和解除当前文章关联。
- `tag_library_manager` 负责标签库展示、使用次数和受保护删除。
- 两个控件只管理表单状态，不直接向 GitHub 或本地文件系统写入内容。
- 标签库查询失败时，文章中原本已有的标签保持可见和可移除，但禁止创建新标签；标签库管理页禁止删除。

### 3. 后端同步层

Decap CMS 版本固定为 `3.15.1`。后台入口启用手动初始化，在 `CMS.init()` 之前包装 `github` 与 `proxy` 后端的文章保存出口：

- 其他后端方法与非文章保存请求原样透传。
- 保存文章前，从待提交文章数据取得最终 `tags`。
- 重新读取最新的 `src/data/tag-library.json`，避免依赖进入编辑页时的旧快照。
- 如果没有缺少的标签，沿用普通单文件保存。
- 如果存在新标签，生成更新后的标签库文件，并将文章文件与标签库文件一起交给一次 `persistEntry` 调用。
- GitHub 后端使用同一提交保存两个文件；本地 Proxy 后端使用同一次保存请求写入两个文件。

包装两个后端是必要条件：开发态检测到 `local_backend` 后，Decap 会从配置的 GitHub 后端切换到 Proxy 后端。同步层不能只覆盖线上路径。

## 保存数据流

```text
输入或选择文章标签
        |
        v
标签只进入当前文章表单
        |
        v
用户保存文章
        |
        v
读取最新标签库并计算缺少标签
        |
        +-- 无新标签 --> 普通保存文章
        |
        +-- 有新标签 --> 文章文件 + 标签库文件
                              |
                              v
                     一次 persistEntry 保存
                              |
                  +-----------+-----------+
                  |                       |
                成功                    失败
                  |                       |
        两个文件同时生效        保留表单，可直接重试
```

取消编辑不会触发同步层，因此待创建标签不会残留在全局标签库中。从文章移除标签只改变文章的最终 `tags`，不会从标签库文件删除标签。

## 并发与异常处理

- 标签库加载失败时，不允许创建新标签或删除标签；当前文章已有标签保持可见，用户可以取消其文章关联。
- 保存前必须重新读取标签库，不能直接覆盖其他会话刚新增的标签。
- 保存失败时保留文章表单和待创建标签，允许用户修复网络问题后重试。
- 多文件保存失败不得回退为先保存文章、再单独保存标签库。
- GitHub 返回内容冲突时，提示刷新后台重新载入最新内容后再保存。
- 删除标签前重新统计文章使用情况；统计失败或结果不确定时禁止删除。
- 删除保存发生冲突时保持标签库原值并提示刷新，不静默覆盖远端修改。

## 数据约束

- 标签库格式继续为 `{ "tags": string[] }`。
- 新标签去除首尾空格，空字符串不能创建。
- 完全同名标签复用，不重复写入标签库。
- 大小写不同但字符串不完全相同的标签暂不合并。
- 合并标签库时保留所有历史标签，包括使用次数为零的标签。
- 所有写入保持 BOM-free UTF-8 和稳定 JSON 格式，避免无关文件抖动。

## 验收与测试

### 单元测试

- 标签规范化、空值拒绝和完全同名去重。
- 大小写不同标签保持独立。
- 缺少标签计算与标签库稳定合并。
- 文章使用次数统计和删除许可判断。

### CMS 集成测试

- 输入不存在的标签时显示创建项，Enter 和点击均可创建待保存标签。
- 创建后可继续添加多个标签，已有标签仍提供搜索提示。
- 从文章移除标签只更新文章表单。
- 保存无新标签文章时只提交文章文件。
- 保存含新标签文章时，一次 `persistEntry` 同时包含文章和标签库。
- 保存失败时不产生第二次独立保存，且表单值仍可重试。
- 取消编辑不写入标签库。
- GitHub 与 Proxy 包装器执行相同的同步规则。

### 标签库管理测试

- 显示每个标签的文章使用次数。
- 使用中的标签无法删除。
- 未使用标签必须确认后才能删除。
- 从最后一篇文章解除标签后，该标签仍存在于标签库。
- 标签库或使用情况加载失败时删除入口禁用。

### 回归验证

- 运行 CMS 相关 Vitest、完整 `npm test`、`npm run check` 和 `npm run build`。
- 同时启动 Astro `127.0.0.1:4321` 与 Decap Local Backend `127.0.0.1:4322`，在真实后台验证创建、保存、取消和删除流程。
- 使用线上 GitHub 后端验证一次新建标签的多文件提交，确认单个提交同时包含文章与 `src/data/tag-library.json`。
- 验证未跟踪的本地测试文章不会被测试或实现过程擅自删除、覆盖或提交。

## 完成标准

只有在以下条件全部满足时，本功能才算完成：

- 新文章可在标签输入中选择旧标签并创建多个新标签。
- 新标签仅在文章保存成功后进入全局标签库。
- 文章与标签库通过同一次后端保存提交，没有半提交路径。
- 取消或保存失败不会污染标签库。
- 文章侧移除不会删除全局标签。
- 标签库页面能够显示使用次数，并严格执行使用中禁删、未使用二次确认。
- 本地 Proxy 与线上 GitHub 路径均通过自动测试和真实后台验证。
