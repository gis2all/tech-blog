## 时间线：一年出头走完"从发起方案到公共标准"

| 时间 | 事件 |
| --- | --- |
| 2025-05 | [Coinbase CDP](https://docs.cdp.coinbase.com) 发布 [x402 白皮书（V1）](https://github.com/x402-foundation/x402/blob/main/specs/x402-specification-v1.md)，激活闲置近 30 年的 HTTP 402 状态码 |
| 2025 年底 | [x402 V2 规范](https://github.com/x402-foundation/x402/blob/main/specs/x402-specification-v2.md) 重构：[CAIP-2](https://chainagnostic.org/CAIPs/caip-2) 多链标识、Session Token（可选扩展）、`upto` 按实际消耗扣款 |
| 2026-04 | Coinbase 宣布将 x402 知识产权与核心代码库移交 Linux 基金会 |
| 2026-07-14 | [Linux Foundation 宣布 x402 基金会正式运营](https://x402.org/linux-foundation-announces-operational-launch-of-x402-foundation-to-standardize-internet-native-payments-for-ai-agents-and-applications/)，40 家组织加入 |

移交时点的生态数据：据 [x402.org](https://x402.org) 实时统计，近 30 天处理超过 7500 万笔交易、清算金额超 2400 万美元、约 9.4 万买家和 2.2 万卖家。协议不是没人用才捐出去——它是在被大量使用之后才移交的。

## 移交的原因：信任悖论

x402 早期面临一个尖锐的质疑：它是 Coinbase 一家上市公司的发起方案，商家和智能体很难把支付基础设施押在一个商业对手身上。支付赛道对稳定性的要求极高，单一实体控制协议 = 厂商锁定风险。

Coinbase 的选择是彻底放手：知识产权 + canonical 核心代码库全捐，治理架构完整移交 Linux 基金会托管。效果是消除"协议最终会被 Coinbase 垄断"的信任悖论——协议成为中立公共资产，任何商家接入时不需要评估 Coinbase 的商业动机。

这个动作的逻辑：支付标准的中立性本身就是竞争力。HTTP、TCP/IP 之所以成为互联网底座，恰恰因为没有哪家公司拥有它们。x402 想成为"互联网的原生支付层"，就必须走同样的路。

## 40 家成员：从云到卡组织

x402 基金会首批成员覆盖了从云服务到卡组织的完整链条（名单来自 [Linux Foundation 公告](https://x402.org/linux-foundation-announces-operational-launch-of-x402-foundation-to-standardize-internet-native-payments-for-ai-agents-and-applications/)，2026-07）：

- **Premier 成员（17 家）**：Adyen、AWS、American Express、Circle、Cloudflare、Coinbase、Fiserv、Google、Mastercard、Monad Foundation、MoonPay、Ripple、Shopify、Solana Foundation、Stellar Development Foundation、Stripe、Visa
- **General 成员（18 家）**：Aleo、Fireblocks、Galaxia Moneytree、Hecto Financial、Injective、KakaoPay、Kite AI、LayerZero Labs、Merit Systems、NEAR Foundation、Orthogonal、Polygon Labs、Quant Network、SKALE、t54 labs、utexo、World Liberty Financial、zerohash
- **Associate 成员**：BSV Association、Cardano Foundation、Casper、OMA3

两个信号。**Visa 和 Mastercard 进来了**：卡组织把 x402 当新渠道而不是敌人。**Stripe 也在 Premier 名单里**：它同时与 Tempo 合作推动 MPP（见下节），是标准之争里两边下注的典型。当一个协议同时被 AWS、Visa 和 Stripe 接受，它就不再是某个公司的私有协议。

## 双雄格局：x402 vs MPP

x402 不是唯一在抢机器支付标准的。Stripe 与 [Tempo](https://tempo.xyz) 共同提出了[机器支付协议（MPP）](https://github.com/tempoxyz/mpp)（[mpp.dev](https://mpp.dev)，已提交 IETF 讨论），形成双雄对峙：

| 维度 | x402 | [MPP](https://github.com/tempoxyz/mpp) |
| --- | --- | --- |
| 设计哲学 | 传输层原生、无状态质询（V2 可选 Session Token 提供有状态会话） | 有状态客户端认证 + 持久 Session |
| 握手方式 | 单次 HTTP：402 + PAYMENT-REQUIRED 自发现 | 业务调用前先建立会话通道 |
| 链 | 链中立设计（Base/Solana/Stellar/Hedera/Aptos…） | 与 Tempo 生态及 Stripe 收单体系深度整合 |
| 结算资产 | 链上稳定币（USDC/EURC），协议层 0 抽成（Facilitator 可收服务费） | 依赖 Tempo 生态或 Stripe 通道 |
| 背靠 | Linux 基金会 + 40 家成员 | Stripe + Tempo |

这是两种哲学的对撞：x402 赌"HTTP 本身就是支付协议"，无状态、零集成成本、链中立；[MPP](https://github.com/tempoxyz/mpp) 赌"机器支付需要会话级基础设施"，有状态、可预测、深度整合 Stripe 的收单体系。谁赢不取决于技术优劣，取决于开发者接入成本和应用场景。

## 标准之争的启示

对协议本身，移交 Linux 基金会意味着三件事：

1. **治理稳定**：协议演进不再看 Coinbase 的脸色，版本迭代（V1→V2 的重构已经证明规范会演进）走基金会流程。
2. **采用门槛降低**：企业采购层面，基金会托管是合规和法务的绿灯：接入一个基金会标准比接入一家公司的私有协议容易得多。
3. **竞争焦点转移**：协议层的竞争仍在继续，但重心正向应用层扩散（谁的服务多、谁的工具好），这也是第五篇生态地图里消费端项目繁荣的原因。

## 小结

| 问题 | 答案 |
| --- | --- |
| 谁发起的 | Coinbase（2025-05 白皮书） |
| 谁在治理 | Linux 基金会托管，x402 基金会运营（2026-07 正式启动） |
| 为什么移交 | 消除单一实体垄断的信任悖论，支付标准需要中立性 |
| 成员 | 40 家：AWS/Google/Cloudflare/Shopify + Stripe/Visa/MC/Amex/Adyen + Circle/Ripple/Solana 基金会等 |
| 最大对手 | Stripe 系 [MPP](https://github.com/tempoxyz/mpp)（有状态会话 vs 无状态传输原生） |
| 生态现状 | 近 30 天 7500 万+ 笔交易、2400 万+ 美元清算（x402.org） |

x402 走了一条少见的路径：先由公司发明，再主动放弃控制权，交给中立基金会治理。HTTP 402 等了近三十年才被启用，从公司资产变成公共标准只用了一年出头。
