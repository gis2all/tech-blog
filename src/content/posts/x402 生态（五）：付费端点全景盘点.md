协议讲完了，代码跑通了，Facilitator 也剖析过了。这篇把视野拉开，盘点 x402 生态里正在跑的项目和它们各自解决的问题。据 [x402.org](https://x402.org) 实时数据，近 30 天生态处理了超过 7500 万笔交易、清算金额超 2400 万美元，有约 9.4 万买家和 2.2 万卖家；社区目录（[x402scan](https://x402scan.com) 等）已索引数万个付费端点。这个生态可以分成五大类。

## 第一类：基础设施与开发工具——给 API 加支付墙

这一层解决"如何以最低代码量给 API 加上 x402 支付墙"。

| 项目 | 定位 | 一句话 |
| --- | --- | --- |
| [tollbooth](https://github.com/Fewsats/tollbooth) | 开源 x402 API 网关 | 一份极简 YAML 配置，在现有 API 前架起动态定价、多代理、SSE 流式的计费前台 |
| [ampersend / Locus](https://ampersend.ai) | Agent 花费控制中心 | 托管 Agent 私钥 + 可视化预算面板（单次上限、每日上限、API 白名单） |
| [thirdweb](https://www.thirdweb.com) | 多语言 SDK | 提供 x402 支付钩子与多链接入能力 |
| [Mogami](https://github.com/mogami-tech/x402-java-client) | Java SDK | Java 生态的 x402 实现 |

[ampersend/Locus](https://ampersend.ai) 这类"花费控制中心"解决的是 Agent 经济的核心矛盾：既想让 Agent 自主花钱，又不想给它一把无限额的私钥。方案是私钥托管 + 严格限额 + 白名单，人类操作员在面板上随时调整。这是"可编程限额"思路的产品化（第一篇提过这个设计动机）。

## 第二类：Facilitator——链下清算层

上一篇讲过的角色，这里只列生态现状：

- **[Coinbase CDP](https://docs.cdp.coinbase.com)**：托管服务，生态中使用最广泛的实现，内置 KYT/OFAC 合规
- **[x402-rs](https://github.com/x402-rs/x402-rs)**：Rust 实现（283+ star）
- **[ZeroPay](https://github.com/zpaynow/ZeroPay)**：GPL-3.0 开源自托管，Rust + PostgreSQL + Redis，Docker 几分钟起
- **[OpenZeppelin relayer 插件](https://github.com/OpenZeppelin/relayer-plugin-x402-facilitator)**：面向 Relayer 场景的官方生态插件

## 第三类：客户端与钱包——机器和人的付款工具

| 项目 | 定位 | 说明 |
| --- | --- | --- |
| [1Pay.ing](https://github.com/ldclabs/1paying) | x402 结账钱包与支付网关 | SvelteKit 构建，免充值即时微支付、可定制结账面板 |
| [Primer](https://x402.primer.systems) | x402 Chrome 钱包扩展 | 人类浏览网页时遇到 402，钱包签名毫秒解锁；[MultiClaw](https://github.com/primer-systems/multiclaw) 是本地多 Agent 私钥管理器 |
| [x402-proxy](https://github.com/cascade-protocol/x402-proxy) | CLI / 本地 MCP 中转工具 | 命令行调用付费 API，底层自动处理签名重试 |
| [AgentCash](https://github.com/Merit-Systems/agentcash-router) | Agent 资金托管 + 付费服务搜索 | Claude Code、Cursor 等工具授权后动态发现并支付付费 API，终端里绑定"企业卡"式限额 |

Primer 这类浏览器钱包说明 x402 不只服务机器：遇到 402 的网页，钱包点一下签名就解锁，没有注册、没有绑卡。这是"无平台账号付费"的雏形。

## 第四类：消费端付费服务——生态里商业收入的主要来源

这是直接产生商业收入的 API 市场，按领域分：

**网页抓取与搜索**：[Firecrawl](https://firecrawl.dev)、[Exa](https://exa.ai)、[Zyte](https://www.zyte.com)——AI 爬虫按次付费（单次低至 $0.001）获取清洗过的 markdown 网页，替代验证码满天飞的免费抓取。

**社交与实时数据**：[Neynar](https://neynar.com)（Farcaster 数据）、[twit.sh](https://twit.sh)（Twitter/X 数据，标准 v2 JSON 格式，无注册门槛，按次计费）、[Gloria AI](https://github.com/cryptobriefing/gloria-lucid-agent)（新闻情报，x402 接入）。

**加密数据与 DeFi 分析**：[CoinGecko x402 API](https://www.coingecko.com) 等，量化/套利 Agent 无需预充值，按次拿实时价格、流动性深度、聪明钱包信号。

**LLM 推理**：[AskClaude](https://askclaude.shop)：按次付费的 Claude 消费终端，不绑卡不订阅（价格以官网为准）。

**营销与创作**：[AdPrompt](https://adprompt.ai)：把广告创意拆成三个 x402 保护的 API 路由（品牌分析、策略生成、创意生成）。

这些项目的共同模式：把"包月订阅"拆成"按次付费"。以前一个量化 Agent 要买 $99/月的行情套餐，现在一次调用几分钱，用多少付多少。对 Agent 来说，这直接改变了成本结构和接入门槛。

## 第五类：目录与分析——生态的发现层

端点多了就要被发现、被监控：

- **[x402scan.com](https://x402scan.com)**：生态浏览器（类似区块链浏览器的角色）
- **[x402station](https://github.com/sF1nX/x402station-mcp)**：实时服务监控与数据分析平台（MCP 适配）
- **[Agentic.Market](https://agentic.market)**：x402 服务发现目录
- **[Pay.sh](https://pay.sh)**：付费 API 目录
- **[x402-list.com](https://x402-list.com)**：x402 服务生态搜索与发现

这一层还很早期，但方向明确：数万个端点如果没有索引和监控，Agent 根本找不到它们。目录+分析是生态规模化的必经环节。

## 生态观察

1. 钱正在从"订阅"流向"按次"。几乎所有消费端项目都在做同一件事。这不是 x402 独有的趋势（LLM API 本身按 token 计费），但 x402 把"按次付费"从 API 领域扩展到了数据、内容、社交信息——任何可以被 HTTP 访问的东西。
2. **安全层正在形成**。花费控制中心（[ampersend/Locus](https://ampersend.ai)）、风险引擎（[BlackSwan](https://blackswan.wtf)）、安全网关（[AI Security Guard](https://aisecurityguard.io)）：Agent 花钱的安全问题催生了专门的赛道（第七篇展开）。第一篇里"可编程限额"的设计动机，正在变成真实的产品。
3. 浏览器钱包（[Primer](https://x402.primer.systems)）、结账面板（[1Pay.ing](https://github.com/ldclabs/1paying)）这类产品把 x402 带回了人类场景：最初为 Agent 设计，但"无账号付费"对人类用户同样成立。
4. **基础设施层已有多个活跃实现**。Facilitator 和 SDK 由 Coinbase、[thirdweb](https://www.thirdweb.com) 等头部项目主导，创业空间集中在消费端服务。

## 小结

| 层级 | 代表项目 | 解决什么 |
| --- | --- | --- |
| 基础设施/工具 | [tollbooth](https://github.com/Fewsats/tollbooth)、[ampersend](https://ampersend.ai)、[thirdweb](https://www.thirdweb.com) | 给 API 加支付墙、管 Agent 的钱包 |
| Facilitator | [Coinbase CDP](https://docs.cdp.coinbase.com)、[ZeroPay](https://github.com/zpaynow/ZeroPay)、[x402-rs](https://github.com/x402-rs/x402-rs) | 验证签名、垫 Gas、广播结算 |
| 客户端/钱包 | [1Pay.ing](https://github.com/ldclabs/1paying)、[Primer](https://x402.primer.systems)、[AgentCash](https://github.com/Merit-Systems/agentcash-router) | 自动签名、浏览器解锁、花钱限额 |
| 消费端服务 | [twit.sh](https://twit.sh)、[AskClaude](https://askclaude.shop)、[Firecrawl](https://firecrawl.dev)、[CoinGecko](https://www.coingecko.com) | 按次付费的数据与功能 |
| 目录/分析 | [x402scan](https://x402scan.com)、[x402station](https://github.com/sF1nX/x402station-mcp)、[Pay.sh](https://pay.sh) | 发现与监控端点 |
